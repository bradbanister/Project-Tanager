Prompt:

This sounds great for JSON -> relational database. What would it look like to do relational database -> JSON?

Response:

Yes, you can absolutely reverse the process to generate structured JSON from your relational tables using the exact same metadata. This process is often called "un-flattening" or "rehydrating" the data.

The core principle remains the same: your application is a metadata-driven engine. Instead of deconstructing a `JObject`, it will now be **assembling** a `JObject` by querying the database and using the metadata as the assembly instructions.

-----

## Core Concept: Query, Group, and Assemble 🔄

Your engine will perform these main functions:

1.  **Read the Metadata:** Understand the target JSON structure and which tables/columns hold the data.
2.  **Generate a Query:** Dynamically build a single, efficient SQL query that joins the parent and child tables together.
3.  **Execute and Group:** Fetch the flat, joined data from the database and then group the rows by the parent entity's primary key. This is the most crucial step.
4.  **Assemble the JSON:** Iterate through the grouped data, building a nested `JObject` structure in memory that mirrors the desired JSON output.

-----

## Key Components and Implementation Steps

### 1\. Leverage the Same Metadata

Your existing metadata file is perfect for this. The engine will now interpret the properties differently:

  * `tableName` and `columnName`: Used to build the `SELECT` and `FROM` parts of the SQL query.
  * `relationships`: Used to build the `JOIN` clauses.
  * `jsonPath`: Used as the **target location** to place the data when building the output `JObject`.

### 2\. Dynamic Query Generation

To avoid multiple database trips, the best approach is to generate a single query that fetches all the necessary data at once. You'll use the metadata to construct a `SELECT` statement with `LEFT JOIN`s.

Using our previous metadata example, the engine would generate a query like this:

```sql
SELECT
  o.OrderId,
  o.OrderDate,
  o.CustomerName,
  o.EventId,
  oi.OrderItemId,
  oi.ProductSKU,
  oi.Quantity,
  oi.UnitPrice
FROM
  Orders o
LEFT JOIN
  OrderItems oi ON o.OrderId = oi.OrderId
WHERE
  o.OrderId = @SomeId; -- Or whatever criteria you use
```

Your engine builds this query by identifying the parent table (`Orders`) and then joining each related child table (`OrderItems`) based on the `relationships` array in the metadata.

### 3\. Database Execution and Grouping

Again, **Dapper** is the ideal tool. You can execute the query and map the results into a list of dynamic objects.

```csharp
using Dapper;
using System.Data;

// Assume 'connection' is an open IDbConnection
// Assume 'sqlQuery' is the dynamically generated query from step 2
// Assume 'queryParams' contains { SomeId = "ORD-500" }

var flatResults = await connection.QueryAsync<dynamic>(sqlQuery, queryParams);
```

The `flatResults` will look something like this in memory, with the parent `Orders` data repeated for each child `OrderItem`:

| OrderId | OrderDate | ProductSKU | Quantity |
| :--- | :--- | :--- | :--- |
| ORD-500 | 2025-08-18 | A-001 | 2 |
| ORD-500 | 2025-08-18 | B-002 | 1 |

Now, you use LINQ's `GroupBy()` to group these flat results into a structure that's easy to process.

```csharp
// Group by the parent's primary key
var groupedByOrder = flatResults.GroupBy(row => row.OrderId);
```

### 4\. Assembling the JSON Dynamically

This is where you build the output JSON using **Newtonsoft.Json's `JObject` and `JArray`**.

You'll iterate through your grouped results. For each group (which represents one complete parent `Order` and all its `OrderItems`):

1.  **Create the Parent Object:** Take the first row from the group to get the parent data (since it's duplicated). Create a `JObject` for the order.
2.  **Populate Parent Properties:** Use the metadata's `jsonPath` values to place the data. You'll need a helper function that can parse a `jsonPath` like `$.customer_details.name` and create the nested `JObject`s (`customer_details`) as needed.
3.  **Create and Populate Child Array:** Create a `JArray` for the items. Iterate through *all* rows in the current group. For each row, create a new `JObject` for the `OrderItem`, populate its properties (`sku`, `quantity`, etc.), and add it to the `JArray`.
4.  **Attach the Child Array:** Attach the newly created `JArray` to the parent `JObject` at the location specified by the child entity's `jsonPath` (e.g., `$.order.items`).

#### **Conceptual Code for Assembly**

```csharp
using Newtonsoft.Json.Linq;

var root = new JObject(); // The final JSON document

foreach (var orderGroup in groupedByOrder)
{
    var firstRow = orderGroup.First();

    // Create the main 'order' object
    var orderObj = new JObject();
    orderObj.Add("id", new JValue(firstRow.OrderId));
    orderObj.Add("date", new JValue(firstRow.OrderDate));

    // Create and populate nested object for customer details
    var customerDetailsObj = new JObject();
    customerDetailsObj.Add("name", new JValue(firstRow.CustomerName));

    // Attach nested object
    orderObj.Add("customer_details", customerDetailsObj);

    // Create the items array
    var itemsArray = new JArray();
    foreach (var itemRow in orderGroup)
    {
        if (itemRow.OrderItemId == null) continue; // Handle cases with no children

        var itemObj = new JObject();
        itemObj.Add("sku", new JValue(itemRow.ProductSKU));
        itemObj.Add("quantity", new JValue(itemRow.Quantity));
        itemObj.Add("price", new JValue(itemRow.UnitPrice));
        itemsArray.Add(itemObj);
    }

    // Attach the items array
    orderObj.Add("items", itemsArray);

    // Use a helper to place the final constructed order object into the root
    // based on its jsonPath from metadata (e.g., "$.order")
    // and also place global properties like "purchase_event_id"
    // ... logic to place 'orderObj' and other properties into 'root' ...
}

string finalJson = root.ToString();
```

By following this pattern, your engine can re-create the original nested JSON structure from any set of relational tables, guided entirely by the metadata file.
